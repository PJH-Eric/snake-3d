## 再次執行 loop-engineering：暫停事件交錯

第一輪新增回歸案例：依序失焦、進入暫停、收到恢復事件，但尚未取得焦點。原程式的最後一個事件會直接覆寫 `InputSuspended`，測試以「仍未取得焦點時，恢復事件不得提前解除暫停」失敗，確認缺陷。

修正為分別保存視窗焦點與應用程式暫停狀態，僅在兩者都允許時恢復遊戲。`dotnet run --project GameCheck~/InputTests/InputTests.csproj --nologo` 通過兩種交錯恢復順序及既有輸入／DPI 回歸。此測試執行實際 App 的 C# 回呼與合併狀態，未執行 Unity 的生命週期派送。

重新檢查常見 Unity 安裝位置及專案 Build／Builds，仍未找到 Editor 或可執行 WebGL 產物；上述實際畫面驗收矩陣繼續維持「未執行」。

第二輪檢查新增的 visualViewport 支援與方向重排的交互作用：`ApplyScale` 原本在方向／斷點改變時直接 `Rebuild`，可能在軟鍵盤縮小可視高度時銷毀正在輸入的暱稱或聊天欄位。改為記錄待重排狀態，輸入欄仍 focused 時僅更新安全區與尺寸，結束輸入後才重建；切頁及主動重建會清除待重排狀態。正常與 `UNITY_WEBGL` 條件編譯簽名檢查通過，實際軟鍵盤、組字與旋轉仍未執行驗證。

彈窗鍵盤焦點檢查仍發現背景按鈕未被明確隔離；本次未擴充此功能，避免在缺少 Unity 執行環境下宣稱其互動已修復。後續可依 [Unity CanvasGroup.interactable](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/CanvasGroup-interactable.html) 與 [uGUI Selectable](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/api/UnityEngine.UI.Selectable.html) 實作並驗收背景隔離、焦點限制及關閉後回復。

## 再次執行 loop-engineering：連線生命週期與設定

本次為一個連線修復階段，包含兩輪有新失敗證據的修改：

1. 以 HTTP 回應替身手動推進正式 `Net.Wake`：健康檢查等待中呼叫 `CloseConn`，再回傳連線錯誤。原程式未退出，而是將狀態從 idle 改回 waking；再次進大廳會被 `OpenConn` 的 waking 判斷擋住。新增測試先失敗，再於 HTTP 等待結束後統一檢查 `wantOpen` 與 session，一次修正後通過「離開」「離開後重新進入」及「有效連線仍保留失敗重試」三個情境。此修改在舊請求回應後退出，不宣稱中途終止了已送出的 HTTP。
2. 網址測試先以 `https://` 應立即拒絕的案例失敗。改用 `Uri.TryCreate` 驗證合法 HTTP(S) 主機與基底網址，拒絕會破壞端點拼接的帳密／query／fragment，並正規化大小寫。HTTP→WS、HTTPS→WSS 接受大小寫；同源 fallback 亦使用 URI 解析。格式錯誤、大小寫、HTTPS 混合內容、IPv6、連接埠、服務子路徑、同源與無設定單機案例通過。

已執行：`dotnet run --project GameCheck~/InputTests/InputTests.csproj --nologo` 通過新增及既有輸入／DPI 回歸；`dotnet build GameCheck~/GameCheck.csproj --nologo -p:DefineConstants=UNITY_WEBGL` 成功，仍有四個既有未使用欄位警告；`git diff --check` 通過。
